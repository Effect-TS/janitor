# 02: Run a durable agent conversation

**What to build:** A trusted service-level acceptance driver starts a persistent agent conversation, submits instructions and reads responses and usage. Work continues without another prompt and recovers after runner restart.

**Blocked by:** None (can start immediately).

**Status:** needs-triage

Source: [Accepted implementation handoff](../spec.md). Implement this slice within its accepted contracts and evidence limits.

- [x] Build the separate runner with the accepted pinned OpenCode Workerd SDK and isolated Effect dependency graph. Expose authenticated versioned creation, admission, inspection and cursor-based event contracts; creation and native conversation identity are idempotent.
- [x] Persist immutable input IDs and payloads, ordered handoff records and runner receipts. Workflow submission is not SDK admission; retain unresolved handoff state until native acceptance and prevent later inputs overtaking uncertain earlier ones.
- [x] Persist the wake obligation and arm the alarm before native admission can start work. Implement host-scoped execution, approximately 30-second checks, supervision revision races and pre-host generation/uncertainty/compatibility guards.
- [x] Recover orphaned claims before normal pending-input wake; preserve native queue behavior, provider retries and ten-resumption limit. Enforce five-minute model inactivity at the transport boundary and never force-start terminally failed work.
- [x] Use a real configuration-backed native model resolver and runner-only secret references. Persist session model selection; keep structured questions disabled and ordinary conversational questions supported. Controlled model responses are sufficient for this slice; real-provider validation has its own ticket.
- [x] Read durable events using exclusive cursors and replay-safe cumulative usage. Persist consumer catch-up obligations, including idle transitions, rather than depending only on transient notifications.
- [x] Demonstrate two queued inputs, duplicate IDs before/after inbox promotion, lost admission responses, restart without another message, ordinary question/answer, and interrupted event reads through the acceptance driver. No repository or platform mutation is required.

## Comments

### Implemented, awaiting maintainer evaluation

- `runner/` is the separately built runner Worker: its own pnpm workspace on the registry Effect `4.0.0-rc.112` graph with the pinned OpenCode source vendored by `scripts/vendor-opencode.mjs` (revision `2df00955cb933e977427535d2505e50cbc689c69`). One SQLite Durable Object per session hosts the Workerd SDK (`src/Host.ts`, `src/SessionRunner.ts`) behind the versioned command boundary in `src/Protocol.ts`: idempotent creation with deterministic native identity, durable admission by stable `msg_` id, inspection and exclusive-cursor event reads without host construction, maintenance hold/release and generation-fenced cleanup. Errors distinguish incompatible protocol, stale generation, missing session, blocked initialization and retryable transport.
- Supervision persists the wake obligation and arms the alarm before native admission, rearms before fallible inspection, wakes pending native work, leaves orphaned claims to native recovery with its ten-resumption accounting, and clears only after a supervision-revision recheck. Maintenance, compatibility (`_janitor_*` record plus the native migration journal) and persisted blockers are checked before host construction. The five-minute model inactivity deadline sits at the HTTP boundary; native retries and Retry-After are preserved. The structured question tool is not advertised; shell commands must be foreground with finite timeouts.
- Model configuration is a deployment record set (`src/ModelConfiguration.ts`) with runner-only secret binding references; sessions persist their selection and the real resolver feeds `SessionRunnerModel.resolved`. Controlled model responses come only from the test entry (`test/worker.ts`).
- Janitor side (`apps/cluster/src/Agent/`, migration `0022`): acceptance freezes content, attribution, sequence and runner message id with the handoff intent in one transaction; the `AgentRunnerHandoff` workflow delivers unsettled inputs in order under a per-session lease and retries uncertain admissions by identity; the projection consumer applies events and advances its exclusive cursor atomically, replaces cumulative usage under cursor protection, and persists the next catch-up obligation (30-second active cadence, five-minute idle cadence) before releasing the current one; the minute cron services due obligations and re-requests stalled handoffs.
- Acceptance: runner scenarios in `runner/test/` (Miniflare) cover queued order, duplicate ids before/after promotion, lost replies, crash after admission, interrupted turns, runtime restart, ordinary question/answer, idle races, maintenance, compatibility guards, blockers, cleanup, transport deadlines, retry exhaustion, resumption exhaustion and shell policy. Janitor tests in `apps/cluster/test/Agent/` cover the client classification, ordered handoff, projection replay and interrupted reads; `AcceptanceDriver.test.ts` drives the real runner bundle through the Janitor services.
- Not in this slice: real-provider validation (its own ticket), Sandbox/repository tools, platform delivery and deployment provisioning of the runner bindings.
- Review-recorded deviations: catch-up scheduling is a cron-driven singleton over durable obligation rows rather than a workflow per read (the obligation is the durable part); native session permissions are allow-all until repository tools exist (ticket 05 scopes them); model configuration records carry no provider request settings until real-provider validation defines them; the inactivity deadline wraps the response stream, which is the path the pinned OpenAI-compatible SSE route reads; the `driver` input source exists for the trusted acceptance driver.
