# Repository execution verification results

The bounded execution-contract checks passed using the pinned OpenCode Workerd SDK, Cloudflare Sandbox, R2, Durable Object SQLite, and the authorized private repository `Effect-TS/slopcop-sandbox`. This establishes the selected integration for implementation planning. The fixture is not a production adapter or an unattended-runner test.

## Findings that affect implementation

OpenCode owns the unprefixed SQL table namespace. Its bootstrap deliberately ignores underscore-prefixed embedder tables. Use `_janitor_*` names. The final fixture created `_janitor_state` before bootstrapping OpenCode and passed, including after DO aborts. Earlier evidence suggesting that startup order alone was the requirement is superseded. See the pinned [migration implementation](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/core/src/database/migration.ts).

Native shell capture works in Workerd's temporary filesystem, but a truncated-output notice originally pointed to a file the external repository tools could not read. Keep the native Shell service and copy settled captures into checkpointed workspace storage. Return the external path and commit the checkpoint before exposing successful completion. The native SDK integration exercised that ordering.

Container image updates can temporarily leave an older image serving the fixture. We observed this through missing cwd/PID capabilities during rollout. Adopt only a compatible image/bridge protocol; do not treat a successful Worker deployment as proof that every container has updated. The final run passed with the updated image, including a real PID assertion.

GitHub's PR representation briefly lagged the successfully pushed Git ref. The initial assertion failed despite the correct remote ref. Bounded read-only polling resolved this; the successful rerun did not repeat the push to make the PR representation catch up.

The App initially lacked Contents permission. The user enabled and approved Contents read/write, after which repository-scoped tokens worked. The private key stayed in the existing local `.env.production`; it was not copied into the repository or sent to Cloudflare. Installation tokens expire after an hour, so the broker must refresh by returned expiry and key its cache by installation, repository ID and requested permissions. See [GitHub's installation-token contract](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app).

## Measured bounds and exclusions

The final remote contract run took 53,144 ms across its requests. Successful larger archive stages took 887–2,086 ms; restoration took 1,453 ms after obtaining a replacement sandbox. The complete restore request took 4,845 ms including replacement startup. These are individual synthetic-fixture observations, not production latency guarantees or large-monorepo benchmarks.

The supported fixture process surface covers the standard commands used by native file operations and the shell tool. It explicitly rejects Effect command pipelines and additional file descriptors; this does not restrict pipelines inside a shell command. Output buffering, archive size bounds and typed transport errors need production implementation appropriate to the same contract. The generated-archive extractor is not a general untrusted-archive service. No production Janitor code was implemented here.

The supplemental protected-branch variant could not be enabled: GitHub returned 403 because the selected private repository's plan does not support it. Its temporary branch was removed. The required unavailable-write case passed using a read-only installation token; protected-branch behavior is not claimed as tested. Repository visibility and account plan were not changed.

The actual SDK create/connect path was exercised. Its provider idle/destroy hooks were not used as an unattended scheduler; physical destruction, retention and restoration were exercised through the controller. Automatic idle/wakeup timing, admission after the request ends, model-stream recovery and projection recovery remain the explicit subject of [Verify unattended progress and recovery of the session runner](../issues/11-runner-lifecycle-verification.md), after the supervision decision. They are not hidden completion claims for this ticket.
