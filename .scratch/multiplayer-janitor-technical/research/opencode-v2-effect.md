# OpenCode V2 Effect SDK findings

Research date: 2026-09-11. Source inspection and documentation only. No installation, compilation, agent execution, paid model requests, or runtime compatibility tests were performed.

## Source identity

The requested implementation exists on `anomalyco/opencode` branch `v2`, pinned for this investigation to `2df00955cb933e977427535d2505e50cbc689c69`. Its `@opencode/sdk` manifest declares version `1.18.4` and exports `@opencode/sdk/effect` and `@opencode/sdk/workerd/effect`. That manifest version is a source fact, not verification that an identical registry release is available. The official docs currently recommend a beta tag. Pin an actual package artifact or build this revision before compatibility testing. [SDK manifest](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/sdk/package.json), [Effect SDK docs](https://opencode.ai/v2/docs/build/sdk/effect/).

Its `/v2` path must not be mistaken for the embedded Effect SDK examined here. ## Embedded and remote interfaces

`OpenCode.create()` returns a scoped Effect-native embedded host. `OpenCode.layer()` exposes it as `OpenCode.Service`. Session and event aliases share the client contracts. Internally, the SDK owns a managed runtime and routes requests through an in-process fetch handler. An SDK call using generated protocol code therefore does not imply an external HTTP server. `@opencode/client/effect` is the separate transport client; its entrypoint deliberately avoids Core and Server imports. [Embedded SDK](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/sdk/src/effect/opencode.ts), [host implementation](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/sdk/src/internal/host.ts), [client entrypoint](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/client/src/effect/index.ts).

These are exported APIs, with first-party embedded SDK documentation. Core modules are also broadly exported, but that is not a stability guarantee for their service implementations. The inspected source provides no stable V2 compatibility promise. Prefer documented SDK contracts, and treat direct Core replacement code as coupled to the pinned revision. [Core exports](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/core/package.json).

## Shared-session contracts

The generated Effect API contract contains the following operations. This table describes inspected types, not successful execution. [Effect API types](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/client/src/effect/api/api.ts).

| Need                         | Available contract                                                                                                                                                                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Create session               | `sessions.create` accepts optional ID, title, agent, model, location, metadata, and permissions; returns session info.                                                                                                                            |
| Continue existing work       | `sessions.get({ sessionID })` loads info; subsequent prompts use the same ID. No separate reopen step is required by this API.                                                                                                                    |
| Submit ordinary input        | `sessions.prompt` takes session ID, text, optional message ID, attachments, metadata, delivery and resume flags. It returns an admitted inbox user item, not the completed assistant response.                                                    |
| Observe current work         | `sessions.active()` reports running session IDs. `events.subscribe()` returns an Effect Stream.                                                                                                                                                   |
| Follow/replay session events | `sessions.log({ sessionID, after, follow })` returns a Stream with durable sequence numbers and a synchronization marker.                                                                                                                         |
| Tool activity and failures   | Log event variants include `session.tool.called`, `session.tool.success`, tool errors, and `session.execution.failed`. Presentation still needs a Janitor mapping.                                                                                |
| Usage                        | Session info contains token totals; `sessions.stats` supports time range/project filters. `session.step.ended` includes model-step usage; `session.usage.recorded` covers title/compaction usage. Count both without double-counting projections. |

Prompt delivery defaults to `steer`, which can enter the current execution at a step boundary. The user's agreed next-turn behavior requires explicitly sending `delivery: "queue"`. Inbox records persist with enqueue sequence order. Promotion consumes steers at a step boundary or one queued item at a turn boundary. This is an existing harness distinction, not a reason to invent another conversation scheduler. [Prompt admission](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/core/src/session/session.ts), [inbox promotion](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/core/src/session/inbox.ts).

Caller-supplied message IDs participate in admission reconciliation. They are useful evidence for an ingress idempotency design, but the exact retry contract and crash boundary still need tests. Preserve author/platform identifiers in metadata; Slack authorization and event deduplication remain Janitor responsibilities. [Prompt admission](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/core/src/session/session.ts).

Token categories separate non-cached input, visible output, reasoning, and cache reads/writes. Missing usage is normalized to zero in Core, so dashboard totals cannot imply that every provider reported complete usage. Specify the dashboard's input/output definition against these fields. [Usage conversion](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/core/src/session/usage.ts).

## Workerd and replaceable services

`@opencode/sdk/workerd/effect` exports `OpenCodeWorkerd.create` and `.layer`. It wraps the same embedded SDK with a Workerd profile and accepts Durable Object storage. The profile replaces SQLite, process spawning, snapshots, VCS, filesystem/search, PTY, and config/plugin discovery behavior. Unavailable filesystem/process services do not become a usable git checkout merely because the host starts. A repository execution environment remains necessary. The Cloudflare research ticket traces this boundary in detail. [Workerd Effect entrypoint](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/sdk/src/effect/workerd.ts), [replacement graph](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/server/src/workerd.ts).

The SDK accepts workspace providers and scoped instance configuration; Effect plugins can customize agents, models, and tools. The low-level embedding hook accepts `LayerNode.Replacements`, used by the Workerd profile itself. Selecting remote filesystem/process tools or workspace providers is still a hosting decision. Configuring model/provider credentials and outbound transport must be tested with the chosen provider. [Host options](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/sdk/src/internal/host.ts), [instance configuration](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/sdk/src/internal/instances.ts), [Effect plugin customization](https://opencode.ai/v2/docs/build/sdk/effect/).

The inspected V2 source pins Effect `4.0.0-rc.112`. Janitor currently uses the supplied `pkg.pr.new` Effect revision `ec83cbdb3c0b0f89df627a7895939a359db9f4ab`, so compatible type and runtime identities have not been established. Do not assume replacement layers can cross these versions unchanged. [OpenCode catalog](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/package.json), [Janitor workspace catalog](../../../pnpm-workspace.yaml).

## What remains to prove

Before an architecture verdict, run a bounded no-paid-model experiment that bundles the exact Workerd Effect entrypoint under Janitor's toolchain and dependency resolution, creates and reloads a session with Durable Object SQLite, and verifies queued input and cursor-based event recovery across host recreation. Add a fake model and fake tool to prove errors and usage mapping without paid execution. Separately test real repository filesystem, git, process execution and interrupted mutations in the selected execution environment. Host startup/recovery code exists, but source inspection cannot prove wake-up behavior after platform eviction or exactly-once external tool effects. [Host recovery invocation](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/sdk/src/internal/host.ts), [execution recovery](https://github.com/anomalyco/opencode/blob/2df00955cb933e977427535d2505e50cbc689c69/packages/core/src/session/execution/restart.ts).

The source identity and public API ambiguity are resolved. Direct Durable Object hosting has a concrete first-party implementation to evaluate. Full repository execution compatibility and deployment behavior remain unproven; this research does not select an architecture.
