## Concrete integration requirements

- Represent source IDs and delivery attempt IDs as exact strings at the JSON boundary where needed. Never stringify a number after it has already rounded. Keep attempt IDs distinct from GitHub delivery GUIDs and logical contribution IDs. The verified Workerd source-text reviver is one available implementation for the tested compatibility date.
- For Slack, page only the bound root, deduplicate repeated messages by workspace/channel/`ts`, sort exact timestamps, and enforce the initiating boundary. Do not rely on page concatenation order or a repeated mention for later replies. Filter bot/app and mutation events before original-message admission; preserve their transport receipts separately.
- For GitHub, hydrate a submitted review by its own review ID. The tested standalone/later comments also have submitted review records, which prevents overlap without a time-based debounce. A reply's `in_reply_to_id` identifies its discussion parent, not its batch membership. Keep unclassified or incomplete contributions pending; do not discard them because another review has been consumed. Do not promise that present API pages reconstruct deleted or earlier versions.
- Publish only after durable output intent. Validate marker, author and target during positive reconciliation. Missing lookup results remain uncertain; they do not authorize a retry. Preserve per-session output order while allowing other sessions to progress. Coalesce only pending progress, never final/error/substantive output.
- Scan GitHub deliveries with App JWT and opaque next cursors, processing each page before fetching the next. Filter summaries before retrieving unrelated private details. Persist partial traversal and terminal intake decisions. A fixture can stop after finding its known events; production has no such complete expected-event list.

## Planning gate disposition

The user asked to proceed after confirming ephemeral visibility. The [ticket resolution](../issues/14-platform-delivery-verification.md#answer) carries the following recovery defaults and limits into planning and defers live membership removal/restoration to implementation acceptance:

1. Define accepted feedback as the first successfully captured version, with an explicit incomplete state when hydration cannot establish membership/content. Preserve that version on retries. Exact historical snapshots are not available from mutable paginated reads.
2. Use five-minute recovery scans as the MVP default. GitHub scans the retained delivery window with resumable cursors and rate-aware scheduling; the observed full scan cost is now measured. Slack scans known home threads after their start boundary with overlap. Deleted messages, edited original text never received, expired GitHub deliveries, and never-received Slack starts may be unrecoverable. Record overdue scans and gaps visibly instead of claiming complete catch-up. No fixed sampling interval guarantees losslessness.
3. Use the local access-restoration evidence for this planning gate and retain the live membership removal/restoration test for implementation acceptance. Ephemeral visibility is confirmed by the recipient on the second attempt. Real membership removal/restoration remains a distinct unexecuted check.

No new agent execution loop, authentication architecture, or product behavior was silently accepted by these probes. In particular, no test proved indefinite exactly-once external publication or recovery of absent history.

## Cleanup and validation

Both sandbox PRs from these delivery experiments, #8 and #9, are closed unmerged. Their temporary branches were deleted and scoped installation tokens revoked. Submitted review/comment history remains on those closed PRs as declared in the test plans. All agent-authored ordinary Slack fixture messages were deleted. The temporary Cloudflare receiver was deleted. Control-plane and public requests return 404, and no matching Durable Object namespaces remain. See [cleanup evidence](platform-receiver-cleanup.json). Its app Event Subscriptions will need to be disabled in Slack's dashboard, since a bot token cannot edit app configuration. Local credential files are retained with owner-only permissions outside the repository. No production GitHub webhook URL or signing secret was changed.

Twenty-two local contract checks passed. The Workerd JSON probe passed. Repository validation is recorded in the final results update; fixture-specific results are not a claim that production integration tests exist.

`vp install` passed. All 22 local delivery contract tests and the local Workerd JSON probe passed. The full `vp test` run had 532 passing tests and one 5-second timeout in `GitHubAccess.test.ts`; a focused rerun of that file passed both tests.
