## Retention remains an unresolved contract

The backup API defaults to 259,200 seconds, three days, and requires a positive TTL. Restore checks expiration and rejects an expired backup. The archive and metadata remain in R2 after expiration unless deleted separately. A durable copy of the handle therefore does not provide indefinitely restorable session state. The documented public methods are creation and restore; no renewal or no-expiry option is documented. [Backup API](https://developers.cloudflare.com/sandbox/api/backups/)

The pinned implementation stores `ttl` and `createdAt` in `backups/{id}/meta.json`. Both local and production restore calculate `createdAt + ttl * 1000` and reject if the current time plus a 60-second buffer exceeds that instant. Creation rejects `ttl <= 0`. No renewal method was found in the inspected class. [Pinned create implementation](https://github.com/cloudflare/sandbox-sdk/blob/133939602f28a23ae6bab1d00878d95b3f308394/packages/sandbox/src/sandbox.ts#L6838), [pinned restore implementation](https://github.com/cloudflare/sandbox-sdk/blob/133939602f28a23ae6bab1d00878d95b3f308394/packages/sandbox/src/sandbox.ts#L7372)

A supported sequence can restore a still-valid backup and create a new one with a fresh TTL. This is an inference from the two public operations, not a renewal guarantee. It requires reliable scheduled work before expiry and an outage allowance. A finite TTL, however large, does not meet an indefinite retention promise on its own. Editing internal metadata, using non-finite numbers, or bypassing the SDK's restore check is not a supported retention strategy established by this investigation. Janitor must settle and verify retention before this ticket can close.

The preview package still contains the same metadata TTL calculation and 60-second restore buffer in `dist/sandbox-Bk7fzLpy.js`; switching to preview or attaching extensions does not establish no-expiry backups. Its extensions documentation describes optional interpreter and OpenCode capabilities, not backup lifetime extension. [Preview package artifact](https://registry.npmjs.org/@cloudflare/sandbox/-/sandbox-0.13.0-next.751.1.tgz), [preview extensions](https://developers.cloudflare.com/sandbox/1-0-preview/extensions/)

## Process adapter gap

Stable 0.12.9 supports string commands, separate stdout/stderr output callbacks and streams, background process IDs, status, logs, exit waits, and `kill(signal?: string)`. Its tagged `BaseExecOptions` and `ExecOptions` have no stdin property. The published `dist/sandbox-BtaWcmmG.d.ts` likewise contains no `stdin` or `writeStdin`. This conflicts with rolling stable documentation, which advertises a stdin option. Use the pinned source and published artifact when designing the adapter. [Pinned options and process types](https://github.com/cloudflare/sandbox-sdk/blob/133939602f28a23ae6bab1d00878d95b3f308394/packages/shared/src/types.ts#L18), [published artifact](https://registry.npmjs.org/@cloudflare/sandbox/-/sandbox-0.12.9.tgz), [rolling command docs](https://developers.cloudflare.com/sandbox/api/commands/)

The preview documentation explicitly says process handles have no standard input either. It offers argv execution, binary stdout/stderr, cursor-based logs, process-group completion, and numeric kill signals. Terminals provide interactive PTY input, which does not establish byte-preserving ordinary stdin semantics. Switching to preview alone therefore does not solve a general Effect ChildProcessSpawner adapter. [Preview process contract](https://developers.cloudflare.com/sandbox/1-0-preview/api/processes/)

The adapter needs executable evidence for stdin writes and EOF, binary transport, interruption, descendant processes, and exit status. A custom container bridge or a narrower provider implementation may be necessary; this report does not select either. Stable docs also state that command timeout closes the caller connection while the underlying process can continue. Treating a caller timeout as a stopped writer would make checkpoint capture unsafe. [Timeout behavior](https://developers.cloudflare.com/sandbox/api/commands/#exec)

## Outbound Git credentials

Cloudflare documents trusted Worker outbound handlers that inject credentials outside the sandbox, with per-instance context and Worker bindings. Exporting `ContainerProxy` is required. HTTPS interception uses an ephemeral CA that the runtime attempts to configure for Git and other clients. Interception covers HTTP/HTTPS, not SSH. Local Wrangler supports interception via a sidecar. These are documented capabilities, not verification that Janitor's GitHub App token flow works. [Outbound handlers](https://developers.cloudflare.com/sandbox/guides/outbound-traffic/)

The candidate package imports its Container base and proxy from `@cloudflare/containers` and exports a Sandbox proxy. A complete deployment must pin transitive dependencies as well. The GitHub handler must select the session repository, mint/refresh its scoped installation credential, and use GitHub's actual HTTPS authentication format. Cloudflare's example `x-auth-token` header is illustrative and is not evidence of authenticated GitHub cloning or pushing. Live tests must check redirect handling and ensure credentials do not enter Git configuration, output, or backup content.
