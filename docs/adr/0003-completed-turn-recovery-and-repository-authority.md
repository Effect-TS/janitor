# Preserve completed turns and separate repository authority

The renewed Linux sandbox design preserves completed turns and durably accepted inputs after container loss. An interrupted turn may lose unfinished workspace changes and report interruption. Unknown external write outcomes require reconciliation before retry. This trades per-tool filesystem durability for a smaller recovery protocol. Final success is reported only after a consistent recovery point is saved. Saving may retry without rerunning the model; persistent save failure is reported distinctly from successful completion. Acknowledgement and progress do not wait for the final save.

Repository scripts are untrusted. Broad GitHub and model credentials remain outside the container, and trusted application code authorizes the scoped operations available to it. Publication uses a dedicated DO-controlled tool that checks repository authority and reconciles push and PR outcomes. Shell commands may edit, test and commit locally, but receive no GitHub write credentials. This limits repository code's authority even when it can execute arbitrary Linux commands. The mechanism for consistent backups remains undecided.

After an interrupted turn, Janitor restores the last completed turn's workspace, reports the interruption, and pauses later queued inputs until a teammate explicitly retries or skips the interrupted input. It preserves the accepted input and reconciles uncertain external writes before retry. This avoids silently repeating expensive or externally visible work, or applying dependent instructions to unexpected state. Automatic infrastructure reconciliation must not automatically resume model execution.

Each session retains its latest confirmed workspace recovery point for its lifetime. The previous point is deleted only after its replacement is safely committed. Session deletion removes its backups. This supports recovery without a user-facing history of workspace snapshots; disposable dependency caches can be rebuilt, while unpublished source changes must survive.

Background processes stop before saving a turn's recovery point. Persistent preview servers are outside the initial scope. Future deployments may interrupt active turns without draining them first; they retain completed-turn recovery points and accepted inputs, and affected sessions wait for explicit retry or skip. This avoids a deployment drain protocol while retaining the recovery promise. It does not permit incompatible storage changes to discard retained sessions.
